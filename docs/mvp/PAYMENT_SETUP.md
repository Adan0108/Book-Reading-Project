# Stripe sandbox setup and verification

**Live provider verification: UNVERIFIED.** No Stripe sandbox credentials were available during implementation. Automated fixtures are local test simulations, not real provider transactions. Live keys are explicitly rejected.

1. Use a dedicated Stripe sandbox. Put its test secret key and webhook signing secret into ignored `backend/.env` as `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`. Never place either in frontend configuration. Set `FRONTEND_URL` to the actual browser origin.
2. Install dependencies with `npm.cmd ci` in each package, build the backend, and start configured MySQL/Redis. Back up an existing database before additive migrations. This task applies migrations only to isolated QA data; normal-database deployment is an operator step.
3. Configure a Stripe webhook destination at `/v1/api/payments/stripe/webhook`, using API version **2026-10-28.endive**. Subscribe to `invoice.paid`, `invoice.payment_failed`, `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `checkout.session.completed`, `checkout.session.async_payment_succeeded`, and `charge.refunded`. For local sandbox delivery use the official Stripe CLI listener and its signing secret. Preserve raw bytes; a proxy must not reserialize the body.
4. As an approved author, configure one or two plans. As another reader, open that author's plans and use a Stripe test card in hosted checkout. Confirm the API remains restricted before the signed paid event. Verify the caller-owned status, payment history, active membership, paid chapter/post access and denial for another author.
5. Make a one-time sandbox donation. Check reader history and author income; no membership should be created. Verify amount/currency and the integer platform/author split against the recorded policy snapshot.
6. Replay a provider event and test a renewal, failed invoice, cancel-at-period-end, partial refund and full refund. Check that ledger totals and paid periods do not duplicate. Compare `GET /admin/payments/reconciliation` (ADMIN only) with Stripe records. Check pending/expired quotes and provider delivery errors; do not infer that an expired quote was charged.
7. Record real sandbox event IDs, commands, observed results and environment in `TEST_REPORT.md`, sanitized of secrets and personal data. Only then change external verification from UNVERIFIED.

The app supports USD, fixed-price monthly card subscriptions and one-time donations. Existing subscriptions retain their quoted recurring amount/share. Tier switching, coupons, trials, tax, provider fees, payout onboarding and disputes are outside this sandbox MVP adapter; unsupported invoices fail safely and require review. Refunds are initiated in the provider sandbox/dashboard, then reflected by verified events. There is no live-money or author-payout feature.

For deterministic local browser tests, `frontend/playwright.config.ts` starts `backend/tests/serve-qa.cjs` with `PAYMENT_QA_FIXTURE=1`. It uses only localhost:3307 `publishing_qa`, labels checkout **Payment test simulation**, creates no external financial requests, and delivers SDK-signed fixture events through the real raw webhook route. Do not run this QA harness as a deployment server. Ordinary `npm.cmd start` cannot select that fixture through configuration.
