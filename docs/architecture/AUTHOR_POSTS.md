# Author updates, spoilers and optional artwork

Updates remain text-first: publishing requires text; drafts may be empty. PUBLIC, MEMBERS and TIERS use the same author-specific entitlement service as books and chapters. Spoiler marking is a reader preference, not an access rule. Eligible readers reveal a collapsed native details control; locked teasers contain neither text nor artwork URLs.

An additive migration extends upload purpose with `post` and creates `post_details` and ordered `post_images`. Existing posts default to no spoiler flag and no images. The legacy chapter-linked `fan_arts` API/table retains its original meaning; optional author artwork does not turn chapters into image-only content or introduce a community upload feature.

The existing local File/object URL editor and three-worker signed-upload service also handle up to eight optional post images. Selection, replacement, removal and ordering stay local until Save. The server verifies confirmed assets, purpose, author ownership and exclusive attachment before updating content, flags, order and the save journal in one transaction under the author lock. A small asset repository centralizes these checks for three concrete consumer types; it is not a generic persistence framework. Admin previews use the same ordered image query. The read-only orphan manifest excludes post consumers and still performs no deletion.

Browser saves use UUID request IDs. Concurrent identical requests return one committed result; conflicting reuse returns 409. The journal hashes the operation kind and target as well as the payload, preventing cross-operation key reuse. Legacy callers without a key retain their old contract but cannot replay across requests safely. After an uncertain write response, the form retains a frozen request and successfully uploaded asset IDs. Retry resolves that same save before further editing. Recoverable upload errors retain files for replacement or retry. Local files are not durable across closing the tab; navigation warns about unsaved work.

Artwork uses the existing Cloudinary public delivery policy. API entitlement checks prevent unauthorized URL disclosure, but a previously obtained public image URL is independently fetchable. This is not DRM or expiring protected media delivery. A future provider delivery-policy change must account for legacy assets; no existing cloud asset is deleted or converted here.

Seven real MySQL regressions exercise retries/conflicts, ordering/removal, omitted-field compatibility, foreign/unconfirmed/purpose/attachment rejection, empty drafts and membership expiry. The headed post journey performs two real retained uploads, intentionally loses a committed response, confirms one persisted post, reopens/reorders without uploads, reveals spoilers and checks member-only redaction.
