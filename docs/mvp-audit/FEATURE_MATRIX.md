## Important contract mismatches

- `routes/books/index.ts` applies optional authentication only to chapter content, not TOC. `listChapterHeaders()` therefore receives no user ID through the routed TOC call even for a member: `tocMemberLock=true` in the probe while the same member receives tier chapter content 200.
- Reader `ChapterReadingPage.tsx` uses chapter number ±1 and `currentBook.totalChapters`. That count is the number of published chapters, not the maximum chapter number; drafts/gaps can cause a next button to stop too early or route to an unavailable chapter. This is a code-derived concern, not a completed sparse-numbering browser test.
- `BookDetailPage.tsx` expects `publishedAt` but public headers return `releaseAt`; frontend book types also use member-flag names that differ from `hasMembersOnlyChapters`. Lock dates/badges need contract tests.
- `PublicationEditor.tsx` never sends tier mappings. Selecting `TIERS` sets only chapter visibility; no author control assigns eligible tiers.
- `services/application.service.ts:approve` adds AUTHOR and updates the application, but does not insert `authors`. Only SQL samples and QA fixture scripts provision author profiles.

Admin-defined default tiers, VIP/VIP++ pricing rules, revenue-share settings, report queues and financial totals have no routed implementation. Basic content moderation is P0; these additional pricing/financial configuration features belong to a later enhancement phase unless made an explicit checkout dependency. There are no implemented user/book/chapter aggregate dashboard endpoints; existing database counts and public view fields do not constitute that dashboard.
